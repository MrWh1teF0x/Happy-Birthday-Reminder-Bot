# CONTRIBUTING.md

## Руководство по оформлению коммитов

Хорошо структурированное и информативное сообщение о коммите необходимо для поддержания ясной и понятной истории версий кодовой базы.
Ниже описан шаблон сообщения о коммите, которого мы будем придерживаться.

---

## Формат коммита

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

### Type (обязательно)

Тип изменения, описывающий цель коммита:

| Тип        | Описание                                                  |
| ---------- | --------------------------------------------------------- |
| `feat`     | Новая функциональность для пользователя                   |
| `fix`      | Исправление бага                                          |
| `docs`     | Изменения в документации                                  |
| `style`    | Форматирование кода (отступы, точки с запятой и т.д.)     |
| `refactor` | Рефакторинг кода без изменения поведения                  |
| `test`     | Добавление или изменение тестов                           |
| `chore`    | Рутинные задачи, обслуживание, изменения в инструментарии |

### Scope (опционально)

Указывает модуль, компонент или функциональную область, на которую влияет коммит:

- `ui`
- `solver`
- `database`
- и т.д.

### Subject (обязательно)

Краткое, повелительное заявление, обобщающее изменение.

### Body (опционально)

Более подробное описание изменения, включая причину его внесения и возможные побочные эффекты. Используйте этот раздел, чтобы предоставить контекст.

### Footer (опционально)

Дополнительная информация, например, ссылки на проблемы. Вы **должны** использовать этот раздел для ссылок на соответствующие задачи.

---

## Примеры

```
fix(solver): 0 angle velocity in Rolling
Redefinition of new, Rolling specific, functions from base
equipment class;
```

```
feat(api): add pagination support for listings

Implement pageable responses for GET /api/v1/listings
Add default sorting by creation date descending
Closes #123
```

```
docs(readme): update installation instructions
```

```
refactor(database): optimize user queries with join fetch
```
